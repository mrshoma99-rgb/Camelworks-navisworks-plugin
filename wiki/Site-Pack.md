# Site Pack

> The model reaching the people building it.

Five tools for the people on the floor rather than the people in the model.

**Tabs:** [Setting Out](#setting-out) · [Dimensions](#dimensions) · [Weight](#weight) ·
[Labels](#labels) · [Documents](#documents)

Every tab starts from **Read the selection** — one read, shared across the app, with its age shown
so you know whether it is stale. Where the files go is a ⚙ symbol on the action row.

---

## Setting Out

> Produce the file an engineer loads into a total station and walks the floor with, in site
> coordinates.

**Main action: Take the points.**

Point numbers take a prefix; you tick which points to take — **base, top, centre, start, end**.

**Where the site grid is** lives behind the ⚙ symbol: the northing, easting and level of the model
origin, and the project angle clockwise from grid north, the way it is written on the drawings.
Get it wrong and every point is out by the same amount — which the screen says, in those words.
The recipe is a fact about the project, so it saves and comes back.

If the model's coordinates were never shifted, the file and the screen both warn.

## Dimensions

> How long that run is, how far it sits off the slab and whether those hangers are at centres —
> for every element at once, on a schedule.

**Main action: Measure it.**

Tick what to measure:

- How big each element is, and corner to corner
- How far each sits above its level
- Each to the nearest other one
- The step from each to the next along a run

Heights **name the level they were taken from**, because a derived level is worth less than an
authored one. The schedule is pickable — the failed rows are the ones that go in the email — and
the written file states its unit.

## Weight

> Work out where the weight of a module actually sits, so the hook goes in the right place.

**Main action: Work out where it sits.**

The centre of gravity of Saturday's lift, off the mass the model carries or the volume of the
shapes. The mass-property candidates are read off the selection itself.

The answer says **whether it is a true centre of gravity** or an approximation from volume, and the
position can be copied or boxed so it can be seen rather than read.

This is not a rigging plan: hook positions and sling angles need an engine the product does not
have. The copied position is the honest edge.

## Labels

> Print a sheet of stickers with a code on each and the identifier underneath.

**Main action: Make the labels.**

What the code says is **picked from properties that actually behave like marks** — nearly always
filled in, not constant, short enough to print. The fallback needs no setup.

The loss level is explained in consequence terms: the more the code can lose and still be read, the
bigger it has to be printed.

A `.csv` index is written beside the sheet, so a code can be looked up.

---

## Documents

> Find the data sheets, the site photos and the document-system addresses the model already points
> at.

**Main action: Find what is attached.**

The commissioning engineer asks for the O&M paperwork and the model already points at it. This
follows the pointers and says what is there, what is missing, and **which folders are there and
empty** — which is usually the more interesting answer.

The naming properties are derived from the selection; the root for relative paths is a stated
option, so a job that moves between machines does not lose every link. Click a row to open the
file, or pick rows to copy or open several. The rules save per project.
